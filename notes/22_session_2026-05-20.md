# Session 2026-05-20 — Pick-refinement workflow design and dry-run

## Goal

Augment the pyocto pick set for already-associated events by going back to
the per-station-day PhaseNet + OBSTransformer pick CSVs and accepting
high-quality candidates within predicted-arrival windows. Pyocto's
event hypothesis stays fixed — we are *adding* picks to existing events,
not associating new ones. The expected payoff is a tighter NLLoc σ
ellipsoid (especially σ_z) and possibly promotion of borderline events
across the reliable-tier QC bar.

## Pipeline (designed today, partially implemented)

```
NLLoc v2 hypocenter ──► predicted tP, tS per station (v2 grid)
                                │
                                ▼
                  open window around predicted time
                                │
                                ▼
       search picks/ and picks_obst_01/ for candidates in window
                                │
                                ▼
   sanity gates  (consensus, S–P>0.3s, internal Vp/Vs band, etc.)
                                │
                                ▼
              augmented pick set → NLLoc re-location
```

Important: **the NLLoc v2 hypocenter drives the prediction**, not
pyocto's. The grids were built around the v2 hypocenters; using
pyocto's location instead gives prediction errors of several seconds
(pyocto and NLLoc differ by 5–10 km routinely for marginal events).

## New scripts

- `scripts/42_plot_event_picker_probs.py` — per-event record section with
  PhaseNet/OBST pick boxes overlaid (height = saved prob, span = pick
  start→end). Also embeds the trilinear grid lookup used by every
  downstream refinement script.
- `scripts/43_predict_arrivals.py` — for a single event, prints a
  per-station table of predicted P/S vs. pyocto-observed times.
- `scripts/44_refine_picks_event.py` — single-event refinement driver.
  Two tiers (`gold` / `standard`) with tunable knobs: `--p-window`,
  `--s-window`, `--consensus-tol`, `--vpvs-lo/hi`, `--no-consensus`,
  `--no-corrections`. Writes a record-section figure with refined picks
  drawn as red (P) / blue (S) vertical lines.
- `scripts/45_compute_station_corrections.py` — population-level
  per-station median residuals across the 7,272 reliable-tier events.

## Conceptual lessons (the parts that took longest)

### 1. The velocity model is not truth — can't use it to gate data

First gold-tier attempt used a Vp/Vs ∈ [1.5, 2.1] check on the *picks*
(implied ratio = tS_obs / tP_obs at the same station). For event 14341,
NLLoc placed the hypocenter at z = 0.001 km (essentially at the sea
surface; the gap=212° location is poorly constrained), making predicted
arrivals systematically late. The implied Vp/Vs from refined picks at
that location came out at 2.27–2.50, outside the gate, even though the
picks themselves were correct. The gate killed every legitimate S pick.

This is a deeper trap: any gate that uses a *predicted* time (directly
or via an implied ratio) is using the model as truth. The correct
sanity gates are model-free:

- `tS − tP > 0.3 s` at the same station (always true physically)
- inter-picker consensus (independent confidence signal)
- internal moveout consistency across stations
- post-relocation RMS / σ change

Dropped the Vp/Vs gate. Now the only data-driven gate is S–P spacing.

### 2. Use NLLoc v2 hypocenter, not pyocto's

Initial predictions for event 14341 used pyocto's (lat, lon, depth) =
(-62.462, -58.594, 0.625 km). NLLoc v2 places the same event 7 km away
at (-62.479, -58.448, 0.001 km). The 1D travel-time grids in
`nlloc/time/ORCA_v2.*` were built using the v2 hypocenters, so
predictions from the v2 location are self-consistent by construction.
Pyocto location → systematic 1–3 s residuals that have nothing to do
with the velocity model.

### 3. Picker probabilities aren't continuous — only thresholded peaks

`catalogs/picks*` files store *one row per pick* above the 0.1
threshold: `time, prob, start, end`. No continuous P/S probability
trace. To recover sub-0.1 candidates we'd need to re-pick at a lower
threshold (~few hours GPU). For now the refinement uses the existing
0.1-threshold catalog, which means stations where the picker simply
didn't fire (very weak arrivals at distant stations) cannot be
recovered.

## Test events

### Event 14341  (volcano summit, depth ~0 km, gap=212°)

- Pyocto picks: 10 P + 7 S = **17**
- Refined (gold + relaxed, no Vp/Vs gate): 13 P + 14 S = **27**
- New picks gained: BRA22/BRA23/BRA26 P; BRA13/BRA15/BRA16/BRA18/
  BRA22/BRA27/BRA05/BRA24 S
- Median P residual (refined vs predicted): −0.28 s (systematic early)
- Median S residual: +0.30 s
- The systematic-negative P residual is consistent with NLLoc's
  near-surface depth being biased shallow.

### Event 14343  (sub-array, depth 4 km)

- Pyocto picks: 18
- Refined: 12 P + 16 S = **28**
- Two new far-distance S picks accepted at BRA11, BRA03 (~70 km)
- Median P/S residuals around ±0.3 s

### Event 19366  (location pinned to grid edge — refinement N/A)

- NLLoc placed it at (lat -62.50, lon -60.93, dep 25.4 km) with
  RMS=2.49 s, gap=312°, σ_y=0.03 km (collapsed). The depth and y
  coordinates are both at the v2 grid's extreme edge — classic sign
  that NLLoc's search wanted to move further outside the grid but
  hit the wall.
- Pyocto disagreed by 100 km horizontally.
- The script's prediction attempt returned NaN because my Python
  `TRANS SIMPLE` re-projection from (lat, lon) gives y=70.23 km
  (outside grid max 70.4) while NLLoc's internal projection put the
  event at y=69.99 (inside, barely). The 0.24 km discrepancy is a
  conversion mismatch between my code and NLLoc's lat/lon → grid_xy.
- Fix: in the prediction step, prefer the catalog's `nlloc_x_km`,
  `nlloc_y_km`, `nlloc_z_km` columns directly instead of re-projecting.
- Either way: events whose location is pinned to a grid wall are not
  meaningfully refinable; flag and skip.

## Station corrections (computed but no-op for these events)

- 33,431 valid pick-event pairs (after dropping |residual| > 5 s
  cross-event contamination — 60 % of raw pairs were mis-associations
  with absurd residuals).
- Cleaned per-station median residuals are essentially zero for the
  core ZX OBS array (|median| < 0.05 s for almost every station).
- Largest real corrections: **5M.DCP P +0.26 s, S +0.16 s; 5M.SNW S
  +0.25 s; BRA21 S +0.09 s; BRA05 S −0.12 s**. All small.
- Output: `catalogs/station_corrections.csv`
- Applying these shifted refined-pick residuals by ~0.03 s — within
  noise. Zero picks added, zero dropped on 14341/14343.

**Implication**: the 1D velocity model from `configs/velocity_model.csv`
is already well-calibrated for the ZX array. The big residuals on
specific events are about location (NLLoc origin time + depth bias) or
event-specific issues (mixed-source association), not about
station-by-station bias.

The earlier BRA08 hypothesis (sediment delay several seconds) was wrong
— empirical correction at BRA08 P is +0.005 s. The visible late energy
on BRA08 in event 14343 was something else (likely another event in
the window, or the picker missed the real arrival).

## Open

- **Validation ablation not yet run.** The actual question — does
  augmenting picks improve NLLoc locations? — needs a 50-event
  before/after comparison on σ_x/σ_y/σ_z/RMS/gap. Until that's done,
  the workflow is unvalidated, however carefully designed. Pick 50
  random standard-reliable events, refine, re-locate via NLLoc, plot
  σ_z_before vs σ_z_after.
- Re-picking at a lower threshold (e.g. 0.02) for the days we already
  have, so far stations with weak arrivals can contribute.
- Pyocto cross-event contamination is real (60 % of pick-event pairs
  failed the residual sanity filter when building corrections). The
  associator routinely attaches picks from neighboring events. This
  may be its own pipeline improvement target — sharper window or
  pre-filter step.
- Wider NLLoc travel-time grid or TauP fallback for far-regional
  events like 19366.
